# Классификатор «команда / разговор» — вариант: эмбеддинги + маленький обученный классификатор

Статус: черновик для обсуждения, ничего из этого ещё не реализовано.
Альтернативный кандидат к [`classifier_design.md`](classifier_design.md)
(zero-shot вариант) — решаем ту же задачу, другим способом.

## Задача

Та же, что в `classifier_design.md`: по тексту распознанной фразы
определить, это **команда** или **разговор**. Разница только в подходе
к реализации.

## Подход

1. Готовая предобученная модель эмбеддингов текста (например BERT-based:
   multilingual, либо русскоязычная — `ru-sbert`, `LaBSE`,
   `paraphrase-multilingual-mpnet` и т.п.) превращает фразу в числовой
   вектор, отражающий её смысл. Сама эта модель не обучается заново —
   используется как есть, "из коробки".
2. Поверх векторов — маленький классификатор (логистическая регрессия
   или небольшая сеть), который **вы обучаете сами** проводить границу
   между "командой" и "разговором" по размеченным примерам.

В отличие от zero-shot — здесь классификатор учится именно на ваших
фразах и вашем стиле речи, а не полагается на общее понимание модели.
Это, скорее всего, точнее на специфичных для проекта случаях (см.
обсуждение примера "включи музыку" vs "какую музыку ты слушаешь"), но
требует размеченных данных для обучения.

### Откуда взять обучающие фразы

Не обязательно придумывать и писать все примеры вручную с нуля:

- Копить реальные фразы через `output/recognized.json` в ходе обычного
  использования `rvs`.
- Прогнать их через zero-shot классификатор ([`classifier_design.md`](classifier_design.md))
  для черновой разметки — проверить/поправить её глазами (быстрее, чем
  размечать с чистого листа), и уже на этом обучить эмбеддинг-классификатор.
- Дописать вручную только те случаи, которых не хватает (редкие/крайние
  формулировки).

## Вход

`output/recognized.json` (пишет `req.py`) — как и в zero-shot варианте,
используется только поле `text`.

## Выход

- метка: `command` или `chat`
- confidence / score решения (насколько вектор фразы близок к каждому
  классу)

Как и в zero-shot варианте — пока нет модулей "разговор"/"разбор
команды", результат предполагается отправлять в систему логирования
SMOS (`module: "classifier"`, см. [`logs/PROTOCOL.md`](../../logs/PROTOCOL.md)).

## Выбранная модель эмбеддингов (2026-09-10)

`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (было
`cointegrated/rubert-tiny2`).

Почему сменили:
- **Калибровка.** rubert-tiny2 (2 слоя, ~29M) как замороженный эмбеддер
  даёт грубые векторы — классы у границы налезают, и вероятность головы
  около границы становится шумом. MiniLM-L12 (~118M, дообучен именно на
  парах перефразировок) растаскивает синонимичные фразы — граница чище,
  `predict_proba` реально коррелирует с правильностью. Это предусловие
  для порога уверенности и для fusion
  (`IDEA_swap_swl_and_classifier.md`).
- **Один эмбеддер на проект.** Он же — кандидат в общий эмбеддер офлайна
  SWL (`../../local_brain_design.md` §5): одна копия в RAM на
  классификатор + намерение вместо двух разных моделей.

Цена: ~450 МБ RAM (fp32) против ~120, десятки мс на CPU против единиц.
На RPi ощутимо (не главный приоритет — решение пользователя), на
десктопе/сервере — нет.

Свап — только смена `local_model.embedding_model` в конфиге; код
`train_local_model.py` / `local_provider.py` эмбеддер-агностичен. На
момент смены датасета в проекте ещё нет (BOOTSTRAP), так что
переобучать нечего — первое обучение просто сразу пойдёт на MiniLM.
Плумбинг (train → save → load → predict → proba) проверен на
синтетике.

## Открытые вопросы

- Сколько размеченных примеров реально нужно для приемлемой точности —
  предположительно несколько сотен, но нужно проверять на практике.
- **Замерить калибровку на живых данных** (reliability diagram / ECE)
  MiniLM против rubert-tiny2 — когда накопится реальный датасет. Пока
  выбор MiniLM обоснован рассуждением, а не цифрой.
- `local_provider.local_classify` сейчас отдаёт только метку. Для порога
  уверенности / fusion понадобится вернуть и `predict_proba` — мелкое
  расширение, отдельно.
- Тот же вопрос про порог confidence и поведение при неуверенности, что
  и в zero-shot варианте — возможно, решается комбинацией обоих
  подходов (см. `IDEA_swap_swl_and_classifier.md`).
