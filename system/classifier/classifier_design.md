# Классификатор «команда / разговор» — черновой дизайн

Статус: черновик для обсуждения, ничего из этого ещё не реализовано и не
решено окончательно (подход к модели может смениться).

## Задача

Определить, распознанная `rvs` фраза — это **команда** (пользователь
хочет, чтобы что-то было выполнено) или **разговор** (общение с
ассистентом как с другом — основной режим SMOS).

Это первая точка в системе, где нужно реальное ветвящееся решение (в
отличие от `rvs`, где вся цепочка линейна и без выбора).

## Рассматриваемый подход: zero-shot классификация

Вместо обучения своей модели или LLM с системным промтом — готовая
NLI-модель (natural language inference), которая оценивает, насколько
фраза логически соответствует заданным меткам ("Это просьба выполнить
команду." / "Это обычное общение."), без необходимости в своём
датасете. Работает offline, многоязычные версии поддерживают русский
(например `mDeBERTa-v3-base-mnli-xnli`).

Плюс: не нужно собирать обучающие примеры, легко добавить новую метку
позже. Минус: тяжелее маленькой обученной модели, точность зависит от
формулировки гипотез под метки.

## Вход

`output/recognized.json`, который уже пишет `req.py`:
- `text` — распознанная фраза (это единственное, что реально нужно
  классификатору)
- остальные поля (confidence STT, альтернативы, язык, время) — пока не
  используются классификатором, но доступны

## Выход

Для каждой фразы:
- метка: `command` или `chat`
- confidence / score по каждой метке (на случай, если решение
  неуверенное — что делать в этом случае, ещё не решено)

Пока модулей "разговор" и "разбор команды" не существует — результат
классификации предполагается просто отправлять в уже существующую
систему логирования SMOS (`module: "classifier"`, см.
[`logs/PROTOCOL.md`](../../logs/PROTOCOL.md)), чтобы проверить пайплайн
целиком без необходимости строить downstream-модули заранее.

## Открытые вопросы

- Как классификатор узнаёт о новой фразе — вероятно, тем же способом,
  каким `req.py` следит за `flags/utterance.wav` (поллинг файла).
- Точная формулировка гипотез для меток на русском.
- Порог confidence, при котором решение считается надёжным, и что
  делать при неопределённости (переспросить? по умолчанию считать
  разговором?).
